# 客流闸机采录台

离线读取虚构展馆的闸机事件、票种与入口映射，重建票据进出和分区在场数。仅使用本地合成材料，不联网。

`python -m pip install -e .` 安装，`python -m gateflow demo` 一条命令生成 SQLite 与 JSON/Markdown 报告，`python -m gateflow --help` 查看独立命令，`python -m pytest -q` 运行测试。

来源 Source 以原始字节 SHA-256 幂等保存；Event 以设备和序号去重，身份冲突进入 Issue。GateMap 按事件时间选版本；Ticket 保存票种；Occupancy 与 Decision 由不可覆盖事件重算。进、出、跨区移动要求票据状态相符，撤销必须引用存在的原事件。设备序号断档与心跳缺口降低结论可信度；容量超限单独报告。非法状态不会直接改变在场数。报告包含来源哈希、事件 ID、票种、分区时段与问题证据。业务状态为未入馆、在馆、离馆；结论为可信、超限、证据不足。错误码在 issue.code 中。

Run 记录每次重算状态，Evidence 逐事件连接原始来源哈希与载荷哈希；重算与运行记录在同一事务内写入。

## 布展搬运计划

`exhibit-catalog` 把展品库存（暂存节点、目标节点、目标分区、箱数）登记入 `exhibit`；`exhibit-register` 把真实库存身份、合成有向通道（可带时窗关闭）、班次、搬运车容量、到位期限与两种获授权目标（`min_walk`、`min_max_lateness`）冻结为 `exhibit_move_case`。`exhibit-plan` 对最多 8 件展品、2 组人员的本地案例精确求解：枚举展品归属、子集动态规划遍历全部取放顺序、每段取时间依赖的最短可通行路径，容量与班次全程生效，两种合同共享同一全局 Pareto 前沿分别取字典序最优。路线证据（每段起止节点、通道路径、到达/装卸时刻、车载展品与箱数、库存 ID、目标分区、冻结输入摘要、目标值、最优性说明）写入 `exhibit_plan` 表并输出 JSON/Markdown 报告；`exhibit-verify` 由冻结输入重算并逐段重放路线、核对最优性摘要。计划仅为派工证据，不表明展品已实物交接，也不改变闸机事件、客流或分区结论。库存缺失、重复派送、资格不符、容量不足、节点不可达或所有路线超出班次时报告不可行原因，不静默少搬一件。
